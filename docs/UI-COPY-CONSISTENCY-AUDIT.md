# We Match 页面文案与视觉一致性审查

- 审查日期：2026-08-07
- 审查范围：登录、广场、发布需求、需求详情、组织广场、创建组织、组织详情、用户名片、我的、编辑名片、Agent 接入、管理后台
- 视口：桌面端 1280 × 900、移动端 390 × 844
- 状态：已登录 owner 视角、已登录普通访问视角、未登录公开访问视角；明暗主题均抽查
- 参照：`docs/DESIGN.md`、`docs/PRD.md` 和当前实际渲染

## 结论

整体视觉语言是统一的：颜色、边框、圆角、8pt 间距、无阴影、列表卡片、输入框和明暗主题都比较稳定。当前主要问题不是“风格散”，而是少数页面在标题层级、焦橙使用和术语上出现了规则漂移。

## 待统一项

### P1：优先处理

| # | 页面 / 位置 | 类型 | 当前表现 | 建议统一方式 |
|---|---|---|---|---|
| 1 | 移动端 `/orgs/[id]`、`/u/[id]` | 视觉 / 文案 | 顶部返回栏直接显示组织名或昵称，紧接着的内容卡又重复显示同一名称。需求详情用的是“需求详情 + 需求标题”，三类详情页口径不一致。 | 统一为“通用页面名 + 实体标题”，例如顶部用“组织详情 / 名片详情”，卡内保留实体名称；或顶部只保留返回按钮，避免重复标题。 |
| 2 | `/orgs/[id]`、`/u/[id]`、`/me/api`、`/me` | 视觉 | 同一屏出现多处焦橙操作。例如组织详情同时有“复制”和“复制邀请链接”，小竹名片同时有两处“复制”，Agent 接入同时有两处“复制”。这与设计规范“每个界面最多一处焦橙主控件”冲突。 | 每屏只保留一个橙色主操作；行内复制改为墨色或灰色，成功后再短暂切换状态。表单错误、删除确认和警告也不要复用焦橙。 |
| 3 | `/me?section=agent` 与 `/me/api` | 信息架构 / 文案 / 视觉 | 同一套 Agent 接入能力存在两套页面实现：前者有说明卡和 `AGENT 接入`，后者是独立页 `Agent 接入`；引导句、层级和留白也不同，后续很容易继续漂移。 | 只保留一个内容源。建议抽成共享 `AgentAccessPanel`，`/me` 和 `/me/api` 只负责不同容器；同步标题、引导语和操作层级。 |
| 4 | 浏览器标题 | 文案 / 元数据 | 大多数页面使用“页面名 · We Match”；用户名片也是“小竹的名片 · We Match”。但需求详情是“我提供｜标题”（无品牌后缀），组织详情始终只有“We Match”。 | 统一标题模板为“页面/实体标题 · We Match”；组织详情补动态 metadata，需求详情补品牌后缀。 |
| 5 | 未登录 `/needs/[id]` 与 `/u/[id]` | 流程 / 文案 | 抽查 3 条仍开放的公开需求时，详情页没有任何“登录后联系 / 查看联系方式”入口；进入发布者名片后才出现“登录后查看”。两个页面对同一个对接动作给出的引导不一致。 | 需求详情保留明确的登录 CTA，并与名片页共用同一套联系引导文案；若产品决定必须先看名片，则在详情页明确写“查看发布者名片后联系”。 |

### P2：随后统一

| # | 页面 / 位置 | 类型 | 当前表现 | 建议统一方式 |
|---|---|---|---|---|
| 6 | 名片编辑、本人名片、公开名片、需求表单 | 文案 | 同一权限概念分别写成“共同组织”“共同组织可见”“共同组织成员”；登录权限则有“登录可见”和“已登录用户”等表达。 | 建立唯一术语表。建议控件短文案用“登录可见 / 共同组织可见 / 隐藏”，解释文案再写完整含义。 |
| 7 | `/u/[id]` 未登录联系方式面板 | 文案 | 在用户动作提示后又写“具体内容仅在服务端确认登录后提供。”这是实现说明，语气明显不同于其他面向用户的文案。 | 删除实现细节，只保留“登录后可查看对方向已登录用户开放的联系方式与社媒”和“登录后查看”。 |
| 8 | Agent 接入 | 文案 | 同一页混用 `API KEY`、`API Key`、`Key`，以及 `SKILL`、`Skill`、`CLAUDE CODE`、`Claude Code`；`AGENT 接入` 与 `Agent 接入` 也不一致。 | 产品文案统一为 `Agent`、`API Key`、`Skill`、`Claude Code`；环境变量和真实代码继续保持全大写。 |
| 9 | 页面级标题 | 视觉 | 标准子页标题是 20px；需求详情和组织详情的 `h1` 是 18px，用户名片 `h1` 是 16px。同为页面主标题但视觉权重逐级下降。 | 明确两级标题令牌：页面标题统一 20px；卡内实体名如果保留为次级内容则用 16/18px，但不要同时承担页面 `h1`。 |
| 10 | `/orgs/new` 与其他编辑/创建页 | 交互 / 视觉 | 移动端已有顶部返回按钮，表单底部又有“返回”；而发布需求、编辑名片没有同样的底部返回动作。 | 统一创建/编辑页导航：移动端只用顶部返回；桌面端依赖全局导航，或所有表单都采用同一套“取消 / 保存”动作。 |
| 11 | `/login` | 文案 / 层级 | 页面没有 `h1`，只有 11px 的“手机号登录”；验证码按钮只写“获取”，与设计规范中的“获取验证码”口径不同。 | 将“手机号登录”作为可见页面标题或语义 `h1`；按钮统一为“获取验证码”，倒计时状态可继续用 `60s`。 |
| 12 | `/u/[id]` 需求区 | 文案 | 使用“TA 的广场需求”，而同站其他说明多使用“对方”。中英文混排风格略跳。 | 统一为“对方的广场需求”或“该用户的广场需求”。 |

## 审查阻塞项（非 UI 问题）

当前真实开发库缺少 `needs.preferred_contact` 字段，而代码已经读取该字段；刷新页面后会出现 `SqliteError: no such column: needs.preferred_contact`，Next.js 报错层会覆盖页面。仓库中暂未看到对应迁移文件。

本次视觉检查使用了数据库的临时副本，并只在临时副本中补齐该字段，没有修改真实 `data/we-match.db`。建议补一条正式迁移后再做最终回归。

## 建议执行顺序

1. 先补数据库迁移，恢复真实开发环境可回归状态。
2. 合并两套 Agent 接入内容源，同时统一英文大小写。
3. 修正移动端详情页标题结构和动态 metadata。
4. 收紧焦橙使用，统一权限术语和未登录联系 CTA。
5. 最后复查空状态、表单报错、删除确认、非成员组织视角等状态页。
