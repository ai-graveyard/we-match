# We Match 设计规范

风格：**Braun / Dieter Rams**（迪特·拉姆斯风）。严格网格系统，功能即形式，少即是多——每个元素都要有存在的理由，没有一个像素是装饰。

> 本文描述当前代码对应的设计规范，上线状态以实际部署验收为准。连接制已在 M6 实现；额度赚回与惩罚阶梯已实现，惩罚默认 shadow 模式，见 [QUOTA.md](QUOTA.md)。

## 1. 设计令牌

实现时按此定义 CSS 变量（Tailwind 4 的 `@theme`），**十六进制值不得偏移**：

```css
:root {
  --u: 8px;           /* 8pt 网格基准，所有间距为其倍数（允许 4px 半格） */
  --bg: #F7F7F7;      /* 页面背景 */
  --bg-2: #EFEFEF;    /* 次级底色 */
  --bg-3: #ECECEC;    /* 悬停 / 按压 / 选中底色 */
  --panel: #FFFFFF;   /* 面板：卡片、表单、Tab 栏 */
  --ink: #1A1A1A;     /* 正文、主控件 */
  --gray: #808080;    /* 次要文字 */
  --line: #C9C9C9;    /* 分隔线、边框（1px） */
  --accent: #E8500A;  /* 焦橙——唯一强调色，只给功能性控件 */
  --sans: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
          "Helvetica Neue", Arial, "PingFang SC", "Microsoft YaHei", sans-serif;
  --mono: ui-monospace, "SF Mono", Menlo, Consolas, monospace;
}
```

暗色主题通过 `<html data-theme="dark">` 覆盖以下令牌（同样**不得偏移**）；`--accent` 是品牌常量，明暗一致。切换入口：桌面端顶部导航图标按钮，移动端「我的 → 设置」的「明暗主题」行；偏好存 `localStorage`，无记录时跟随系统：

```css
[data-theme="dark"] {
  --bg: #121212;
  --bg-2: #1A1A1A;
  --bg-3: #2A2A2A;
  --panel: #1C1C1C;
  --ink: #EDEDED;
  --gray: #9A9A9A;
  --line: #333333;
}
```

- 圆角：小控件 8px，面板 12px，**不超过 12px**。
- 分隔一律用 1px `--line`，**不用阴影**。
- **字号阶梯**（按微信小程序 / WeUI 与 iOS HIG 的手机端惯例定档）。每一档都有对应的工具类，**组件里不写 `text-[12px]` 这类任意值**——写死的没法统一调，整套界面只在 `app/globals.css` 的 `@theme` 里换档：

  | 角色 | 字号 | Tailwind |
  |------|------|----------|
  | 页面标题 | 20px / 600 | `text-xl` |
  | 加大正文（姓名、组织名、验证码格） | 17px | `text-base` |
  | 正文、描述、按钮 | 15px / 行高 1.5 | `text-sm` |
  | 次要说明 | 13px | `text-xs` |
  | 辅助文字（等宽元信息、标签、状态、计数、小节标签） | 12px | `text-2xs` |
  | 徽章等极小注记（**下限，不得再小**） | 11px | `text-3xs` |

  `2xs` / `3xs` 是本项目在 Tailwind 自带阶梯下方补的两档，刻意不配 `--text-*--line-height`，行高继承 body 的 1.5——它们只用在单行元信息上，配了行高反而把紧凑表格撑开。

  两处例外，不受这张表约束：**分享图**（`components/share-card.tsx` 的 `Poster`）是导出成 PNG 的固定画布，宽度（`POSTER_WIDTH` 300px）、字号、颜色一律写死——截图用的那棵树挂在屏幕外，不跟视口宽度走；**管理后台**（`app/[lang]/admin`）是内部工具，表格密度优先。

## 2. 品牌标识

标识是 **W 与 M 拧成的双股波线**：墨色一条是 w（随 `--ink` 明暗切换），焦橙一条是 m（`--accent`，品牌常量）。两条线拧一圈半，三处交叉的上下关系交替（橙上、墨上、橙上），像互相咬住的双股弹簧；整个图形 180° 旋转对称——转过来仍是自己，即 "we match" 的含义。

- **唯一实现源**：路径数据与 `LogoMark`、`LogoSpinner` 在 `components/logo.tsx`（保持服务端可渲染），带悬停动画的 `Brand`（标识与字标组合）在 `components/brand.tsx`；SVG 路径数据不得改动、不得目测重画。
- **favicon**：`app/icon.svg`，焦橙圆角方块（圆角 52/240）上白、墨双线；为小尺寸清晰，线宽 18（组件内为 15），是唯一允许的偏差。
- **应用图标**：`app/apple-icon.tsx` 复用 `icon.svg` 铺满焦橙底输出 180×180 PNG（圆角交给 iOS 遮罩）；`app/manifest.ts` 的图标指向 `/icon.svg`。
- **字标**：「We Match」15px / 700 / 字距 -0.02em（大小写混排，不用全大写字距），与标识间距 8px。`Brand` 只有两档：`sm`（标识 16 / 字标 15，默认）与 `lg`（标识 28 / 字标 26，仅登录页），不得随手缩放。
- **品牌口号**：「你有所需，我有所供。」桌面顶部导航放在字标右侧，登录页放在大号字标下方，「我的 → 用户」页脚和分享海报使用同一句；OG 图因默认字体不含中文，使用对应英文 `YOU NEED IT. I CAN OFFER IT.`。其他位置不另写近义口号。
- **单色档**（`LogoMark` 的 `muted`）：两股都走 `currentColor`。只用于列表终点标记、空状态这类「非品牌焦点」的位置，配 `--line`；目的是让标识出现在这些地方时不把焦橙一起带过去。带色的完整标识留给顶部导航、登录页、「我的」页脚、分享海报和 OG 图。
- **加载指示**（`LogoSpinner`）：螺纹旋转——编织图案沿轴向匀速平移，每 1.6s 移动一个波长（`linear` 循环），侧视投影上等效于双股螺旋绕水平轴转动，如螺杆旋进；用于路由级 `loading.tsx`；`prefers-reduced-motion` 下随全局规则静止。
- **禁止**：拉伸变形、改成单色档以外的颜色、加投影、给标识做大面积橙底（应用图标除外）。
- 使用位置：桌面顶部导航、登录页、管理后台头部、品牌页脚（以上用 `Brand`，不手写）；列表终点与空状态（`ListEnd` / `EmptyState`，单色档）；分享海报头部；`app/opengraph-image.tsx`。

## 3. 焦橙纪律（最重要的一条）

**每个界面最多出现一处焦橙主控件**，给当前界面的核心功能控件：

| 界面 | 焦橙给谁 |
|------|----------|
| 广场（需求流） | 「+ 发布」按钮 |
| 发布/编辑需求 | 提交按钮 |
| 需求详情 | 唯一的意图按钮（「我能提供 / 我想了解」，已举手后转为「查看联系方式」）；面板打开后转移给举手表单的提交按钮，连接后转移给交换到的渠道动作，等待回应时面板内不留焦橙 |
| 收到的举手 | 「接受」按钮（「拒绝」为墨色次按钮，但两者点击代价必须相当，见「举手与连接」） |
| 用户名片 | 已登录时为「复制」联系方式按钮；未登录时为「登录后查看」按钮 |
| 组织广场 | 「凭邀请码申请」提交按钮 |
| 组织详情（非成员视角） | 「申请加入」按钮 |
| 组织详情（owner 视角） | 「复制邀请码」按钮（admin / member 视角无焦橙，允许） |
| 编辑名片 | 保存按钮 |
| 登录 | 「获取验证码 / 登录」按钮 |

在主控件之外，允许且仅允许以下三种**微型橙色指示**（对应 Braun 硬件上的电源点 / 档位指针 / 指示灯，不计入上表）：

1. **品牌标识**：logo 双股波线中的焦橙一股（顶部导航、登录页、管理后台、「我的 → 用户」页脚、路由加载指示，见「品牌标识」一节）。列表终点与空状态里的标识一律走单色档，不带这股橙；
2. **Tab 当前项**：底部 Tab 栏 / 桌面顶部导航保持纯文字，当前项文字转 `--accent` 加粗；导航不使用图标；
3. **状态灯**：6px 焦橙圆点（`statusDot`），只用来标记「有一件事此刻成立」，四处：
   - 广场搜索筛选区下方合并展示计数与筛选入口，右对齐；默认为「N 条进行中 · 显示全部」，切换后为「N 条 · 只看进行中」；圆点仅在「进行中」状态亮起；
   - 需要用户留意但不构成动作的系统提示（如登录页「邮件通道还没开通」、Agent 页「Key 只显示这一次」），普通面板 + 墨色标题 + `--gray` 说明，圆点置于标题行首；
   - 通知列表每条行首，未读亮橙、已读转 `--line` 同尺寸灰点（`statusDotOff`）——同一个位置不留空，行与行才对得齐；
   - 「我的 → 用户」通知入口右侧的未读计数，圆点 + `--mono` 12px `--gray` 数字。**不用橙色实心胶囊**：徽章不着橙，焦橙也不做底色（主按钮除外）。

其余一切控件黑白灰。徽章、标签（tag）、分段控件、输入框 focus 态一律不用橙；焦橙不做大面积底色（主按钮除外）、不做装饰图形。出现清单之外的焦橙即违规——多了就成了装饰。

**提示类信息不用警示框。** 橙色边框、警示三角、感叹号图标都是清单外的装饰，而且会跟同屏的焦橙主按钮抢注意力——用户在登录页真正要点的是「登录」。提示要被看见，靠的是位置（紧贴相关控件）和一个 6px 的点，不是加粗边框。表单校验错误另有约定：沿用 `text-accent` 单行文案，不加边框和图标。

## 4. 字体分工

- **等宽（`--mono`）用于一切技术性内容**：标签（tag）、时间戳、邀请码、计数、需求状态、手机号显示。
- **无衬线（`--sans`）用于正文**：标题、描述、昵称、按钮文字。
- 小节标签（如组织主页的「需求 / 成员 / 设置」分段头）：12px / 600 / 字距 0.08em / `--gray`；英文内容全大写。字距只留给这类标签和按钮，正文不加。

## 5. 组件规范

> **交互控件统一使用 shadcn/ui**，源码在 `components/ui/`，注册配置在 `components.json`。Button、Input、Textarea、Label、Select、Calendar + Popover、InputOTP、Switch、ToggleGroup、Tabs、Dialog、AlertDialog、Collapsible、Table、Card 和 Badge 优先复用这些组件；不得新增可见原生 select、date/time/datetime-local、手写遮罩或自制验证码格。`lib/ui.ts` 保留布局兼容常量，按钮常量由 shadcn `buttonVariants` 派生。隐藏表单字段、普通导航链接和品牌图形不属于替换目标。
>
> shadcn 的结构与无障碍行为保留，视觉令牌映射到本项目黑白灰、焦橙、8/12px 圆角、无阴影规范。shadcn 中表示悬停或选中的 accent 样式使用本项目中性色；焦橙只给主动作。

- **底部 Tab 栏（移动端）**：内容高 56px，下方另垫 `env(safe-area-inset-bottom)`，`--panel` 底 + 顶部 1px `--line`；文字 16–17px（`text-base`）；2 项（广场 / 我的），只显示文字、不使用图标；当前项 `--accent` 加粗（见焦橙纪律之「微型橙色指示」），非当前项 `--gray`。桌面端（≥768px）换为顶部导航条：高 64px，底部 1px `--line`，同样保持纯文字导航。
- **范围切换器（广场页顶部，仅登录后显示）**：与「我的」页顶部菜单保持一致，横向纯文字排列并可滚动；当前范围放大为 20px / 600、文字转 `--accent`，其他范围为 15px `--gray`；组织名最多 10 字，菜单项须为完整 10 字预留空间，不得裁切选中态；末尾固定纯图标「+」入口进入组织广场。切换范围时保留当前类型、搜索、标签和开放状态筛选。
- **广场首屏与卡片**：匿名首屏必须在筛选前用一句话说清双边价值，不能只剩一张无解释的需求表。类型筛选在移动端也写完整意图（`全部 / 有人需要 / 有人提供`），不缩成需要用户猜测的单字。广场主列表卡片提供发布者、城市、更新时间、标题、摘要、标签和截止时间，让用户在进入详情前完成第一次匹配判断；「我的需求」和名片内附属列表继续使用紧凑卡片，避免重复信息。
  - 主列表层级固定为：17px / 600 标题、15px 两行摘要、13px 灰色发布者、12px 标签、11px 时间和供需徽章。发布者不加粗，避免和标题争夺注意力；供需徽章高 20px，使用完整文字。
  - 行内边距 16px，标题距作者行 8px、摘要距标题 8px、末行元信息距正文 12px。只保留记录之间的分隔线，不在每条记录内再画横线；无摘要时不补空白占位。元信息可换行，长标题和摘要须能断词。
  - 列表容器裁切子项背景，确保第一条和最后一条的悬停底色不溢出 12px 圆角；键盘聚焦用内侧轮廓线。
- **搜索框**（`components/search-field.tsx`，广场、组织广场、组织成员三处共用）：高 40px，右侧内嵌带分隔线的放大镜提交按钮，同时支持 Enter 提交；按钮必须提供「搜索」无障碍名称，**不能把放大镜作为输入框内的纯装饰**——左边摆一个点不动的图标，等于给了一个假按钮。需要一起带上的筛选参数走 `hidden` 隐藏域，不要另写一份表单。
- **供需类型筛选**：移动端独占一行，使用完整的「全部 / 有人需要 / 有人提供」；桌面端可与搜索框同排。产品意图优先于为搜索框省下 40px 高度，任何断点都不退回需要猜测的单字。
  - 三项使用等宽网格，外框总高 40px（含边框）。复用 `segmentFrame` 外观，不与 `segmentGroup` 的 `inline-flex` 叠加；子项填满框内高度。搜索框设 40px 最小高度，只在桌面横排时分配 `flex-1`，避免在移动端纵排时被压缩。选中项提供 `aria-current`，切换时保留滚动位置。
- **广场排序**：放在搜索区下方，与结果计数和「显示全部 / 只看进行中」同一行；使用无边框的紧凑文字选择器，显示当前值（`最近更新` / `最新发布` / `即将截止`）和向下箭头，不另起一排工具栏、不使用焦橙。切换后原位刷新且不滚回页顶，排序写入 URL，并保留当前范围、搜索、类型、标签和开放状态筛选；控件必须提供「排序」无障碍名称。
- **组织概览卡（我的页）**：每个组织独立成卡，不把多个组织压在同一张列表卡里；卡内展示成员、开放需求与待审批摘要，底部按角色直接提供需求、成员、审批、邀请入口。创建与发现组织拆为卡片外的并列动作。组织详情页顶部用横向 chip 提供同样的区块直达入口，避免依赖长页滚动发现功能。
- **列表行**：`--panel` 底，行内边距 16px，行高 ≥ 48px，行间 1px `--line`；悬停/按压背景 `--bg-3`，过渡 `.12s linear`。
- **按钮**：15px / 600 / 字距 0.06em，最小高 44px（`min-h-11`，iOS 最小点击尺寸；小程序主按钮普遍 16px / 44–48px 高，15px 是配合本项目 Braun 底子的下沿），左右内边距 16px；按压位移 `translateY(1px)`。四档由 `components/ui/button.tsx` 的变体定义，`lib/ui.ts` 提供兼容导出：
  - `primaryBtn`——`--accent` 底白字，每屏唯一，即该屏的焦橙控件；
  - `secondaryBtn`——`--panel` 底 + 1px `--ink` 边框，悬停反色；
  - `inkBtn`——`--ink` 底白字，只给两步确认里的那一下（退出登录、注销账号）。**不用焦橙**：焦橙是「这屏要你做的事」，而确认删除恰恰不该被鼓励；
  - `quietBtn`——1px `--line` 边框 + `--gray` 字，与主动作并列的「取消」。

  **一切承载动作的按钮至少 44px**，不分主次、不分弹窗内外；常规单行仍为 44px，长文案换行时自然增高，同组并列按钮等高。不得压缩文字、溢出或遮盖相邻控件。纯文字的轻量入口（展开确认、撤回、标为已读）走 `textBtn`，12px `--gray`，不占按钮盒子。焦橙主按钮在暗色模式仍使用白字。
- **40px（`h-10`）用于同级选择与搜索控件**：搜索框、范围/分类切换器（广场页顶部、「我的」页顶部）、分段控件（名片对外预览）。它们要么是输入，要么是在同级选项间切换，误点代价接近零，密度比手指余量更重要。管理后台（`app/[lang]/admin`）整体不适用本条。
- **输入框**：高 44px（与按钮同高，同一行里才不会错位；搜索框按上一条用 40px），`--panel` 底 + 1px `--line` 边框 + 8px 圆角，focus 时边框转 `--ink`（不用橙）。多行输入撤掉固定高度、`resize-y`，其余一致。嵌在 `--panel` 卡片里的输入框（举报、举手留言）改用 `--bg` 底以拉开层次，边框和 focus 态不变。
- **分段控件**（表单使用 shadcn `ToggleGroup`，链接式筛选保留 `segmentFrame` / `segmentItem`；供需类型筛选、组织可见性、需求供需、名片字段可见性、名片对外预览）：高 40px、12px 字，1px `--line` 外框，段间 1px `--line`，选中段 `--ink` 底白字，未选中 `--gray` 字。**五处必须同高同字号**——它们在用户眼里是同一个部件，散成四种尺寸就看得出是拼的。
  - 适用于短标签的两三档切换。名片联系方式、社媒的多档可见范围，以及对外预览身份，统一用 shadcn `Select`（`FormSelect` 适配器）的 40px 自绘下拉框，完整保留中英文选项。移动端字段名与多档控件上下排列，不挤成竖排字；二档按钮必须提供选中态无障碍属性。
  - 个人中心栏目按内容宽度排布，空间不足时换行，不能用六等分压缩长标签。组织卡片快捷动作允许换行；成员管理动作在手机上另起一行，审批区先显示申请人，再显示操作按钮。
  - 长链接、昵称、留言允许在容器内断行，不能撑宽页面。列表面板裁切子项悬停底色，普通表单面板不作全局裁切。
  - 分享和联系方式弹窗须把 Tab / Shift+Tab 焦点限制在弹窗内，Escape 关闭后将焦点还给入口，并恢复页面滚动。
- **可点选 chip**（`chip`；需求期限、发布范围、优先联系方式、组织详情的区块直达）：`px-2.5 py-1` 13px，1px 边框 + 8px 圆角，选中态 `--ink` 底白字。与分段控件的分工：chip 可换行、数量不定，分段控件是固定的几档并排。
- **标签（tag）**：`--mono` 12px，1px `--line` 边框 + 8px 圆角，`--gray` 字；选中态边框和文字转 `--ink`。
- **状态徽章**（`badge`）：`--bg-3` 底 + `--mono` 11px `--gray`，`px-1.5 py-px`。用于需求状态、组织可见性、成员角色、待审批这类只读注记。
- **默认头像**：正方形 + 8px 圆角（不用圆形），`--bg-3` 底，使用灰色 Lucide `UserRound` 图标；MVP 不做头像上传。
- **空状态**（`EmptyState`）：单色档标识（高 22，`--line`）+ 一行 `--gray` 文字，居中；需要时文字里带一个行内动作链接。不配插图。
- **列表终点**（`ListEnd`）：列表滚完后居中一个单色档标识（高 12，`--line`），上下留白 32px，代替「没有更多了」这类文案。只给整页主列表用，不给卡内嵌套的子列表用。
- **品牌页脚**（`BrandFooter`）：1px `--line` 分隔线 + 居中 `Brand` + 标语，不放别的——用户协议、隐私政策和版本号都在「我的 → 设置」。**仅移动端**——桌面端顶部导航条已有字标，再放页脚是重复。只出现在两处：广场页「广场」范围的列表末尾（切到组织范围不放），以及「我的 → 用户」末尾（组织 / 需求 / Agent / 设置不放）。广场这两处由页脚兼任列表终点，桌面端则退回 `ListEnd`（`desktopOnly`）。
- **名片联系方式锁定态**（都不使用锁图标、星号打码或字段占位行，都不透露字段类型与数量）：
  - **匿名访客**（已实现）：不渲染任何联系方式或社媒原值。用一个普通面板提示登录，下方放唯一焦橙主按钮“登录后查看”，登录后回跳原名片。
  - **已登录但没有可见联系方式**（已实现）：社媒按权限显示；存在未揭示 connected 字段时，联系方式区域用同款普通面板提示“联系方式在对方接受你的举手后交换”，下方不放按钮——**要举手得去具体的需求上举**，名片页没有可举手的对象，放按钮只会把人带到死路。若对方有开放需求，面板里给一行文字链接指向同页的需求列表。
  - **已连接**（已实现）：显示双方有效连接已揭示且当前可见的字段，旁边标注来源需求（`--mono` 12px `--gray`）。其他字段仍按 `authenticated` / `orgs` / `hidden` 设置过滤；每次接受只新增双方各一项揭示，不会整张名片开放。

    M6 前只有匿名 / 已登录两态，登录后按 `authenticated` / `orgs` 直接渲染，匿名提示文案也相应写的是“联系方式与社媒”。
- **需求快捷联系**：开放且未过期的他人需求在详情页提供**一个**全宽意图按钮。举手和联系是同一个入口的两种状态，**不并列成两个按钮**——并列过一次，两个按钮的文案都是「我能提供」，用户分不清点哪个，页面上还同时出现了两处焦橙。移动端按钮停靠在底部 Tab 上方。面板移动端从底部出现、桌面端居中，必须明确显示需求标题。面板内容随举手状态切换：
  - **未举手 / 被拒 / 已撤回**：按钮是「我能提供 / 我想了解」，面板内是举手表单（留言框 + 自己的联系方式选择器 + 提交按钮，提交按钮是唯一焦橙动作）。选择器下方用 `--gray` 12px 写明「接受后对方将看到你的微信号」。
  - **等待回应**：按钮转为「查看联系方式」，面板首行交代状态。撤回入口只留在页面的「我的举手」里，不在面板内重复。这一态面板内没有焦橙——此刻没有该用户推进的动作，硬凑一个只会误导。
  - **已连接**：按钮是「查看联系方式」，面板内是快捷联系面板（首个可见渠道独占一张卡和唯一焦橙动作，其他可见渠道用次动作，「复制开场白」用墨色次按钮）。
  - 对方没有任何可见渠道时，按钮仍然出现（面板内只有举手表单）——举手本来就不依赖看得见联系方式。反过来，已举手且无渠道可看时不留空入口。

  微信号复制、手机号 `tel:` 拨打、邮箱 `mailto:` 预填，不实现站内私信。未连接时广场需求不再展示「也可以直接联系」——联系方式只在接受后出现在面板里。
- **举手与连接**：
  - 举手表单里的交换预告是**规范要求，不是可选文案**：紧贴联系方式选择器下方一行 `--gray` 12px，写明「接受后对方将看到你的微信号」。用户必须在点提交之前就知道自己给出去什么。
  - 收到的举手：**「接受」与「拒绝」的点击代价必须相当**——同一行、同样尺寸、都不要二次确认。接受是焦橙主按钮，拒绝是墨色次按钮，但绝不能把拒绝藏进折叠菜单或多加一步。发布者一旦觉得拒绝麻烦，就会转向不理会，而不理会是对举手方最差的结果（白等 72 小时）。
  - 举手状态用 `--mono` 12px：`等待回应` / `已连接` / `未接受` / `已撤回`。状态不用颜色区分，只用文字——这里出现第二种颜色就破了焦橙纪律。
  - **「已无回应」**：72 小时无人处理的 pending，文案要中性，不暗示对方失礼；当前已实现。
- **本人对外预览**：名片顶部使用 shadcn `Select` 展示`未登录访客 / 已登录用户 / 共同组织成员`三档；不使用焦橙。预览说明与“编辑名片”入口置于选择器下方。
  - **不设「已连接」档**。预览回答的是「别人看我的名片是什么样」，而连接依赖双方实际发生过的字段交换（见 [PRD.md](PRD.md) 5「已连接不是一种身份，是一段关系」）——脱离具体需求就答不出该显示哪一项：挑一项当示例是瞎猜，把所有`连接后可见`字段都列出来又变成了「我的可见性设置」，那是编辑名片页的事。前三档是身份，给定访问者即可判定；连接是事件，塞进身份切换器只能靠改口径糊过去。
  - `连接后可见`的字段在这三档下一律不显示，改由预览说明条上一行 `--gray` 12px 交代，如「另有 2 项联系方式要在具体需求上接受举手后才交换」。这行只有本人看得到，比一个档位更能讲清「逐条需求、逐项交换」。
  - 这不影响**访问者**视角：已与本人连接的人打开名片时，照常按上面「名片联系方式锁定态」的第三条渲染（那时「哪条需求」是明确的）。去掉的只是本人自己切过去看的入口。
- **额度提示**（QUOTA P3 已实现；发布/举手/接受的服务端额度也已实现，见 [QUOTA.md](QUOTA.md)）：额度是规则，不是惩罚，所以呈现要克制。
  - 计数一律 `--mono` 12px `--gray`，**不用焦橙**——焦橙留给当屏主控件，额度提示挤进来就成了装饰。
  - **平时不显示**：发布按钮、举手表单旁的剩余计数只在剩余 ≤ 3 时出现，形如 `剩余 2 / 8`。天天顶着计数器会诱导用户去想怎么把额度用完。
  - 三处常驻例外，因为它们是需要用户主动管理的：举手表单底部的 `3 个等待回应中 · 还能举手 4 次`、举手表单里的交换预告、「我的」页顶部未处理举手 ≥ 5 时的 `8 个举手等你处理`。
  - **撞墙文案必须带出路**：每条限制都配一个具体的下一步和直达链接，不能只说“已达上限”。当前服务只返回错误文案，出路入口由页面提供，不能假定每条错误都附独立链接；计数和入口见 [QUOTA.md](QUOTA.md) 第 11 节。
  - 撞墙提示沿用现有表单错误样式（`text-accent`），不为额度新增颜色或图标。
- **动效**：仅入场渐显（上移 8px，`.5s ease-out`）、控件过渡（`.12s linear`）与路由加载的品牌标识旋转（见「品牌标识」）；`prefers-reduced-motion` 时全部关闭。

## 6. 布局

- 内容区最大宽度 640px，桌面端居中；页面左右内边距：移动端 16px，桌面端 32px。
- 所有间距取 8 的倍数（4px 半格允许）；一处错位全盘皆输。
- **移动端安全区**：`app/layout.tsx` 声明 `viewportFit: "cover"`，`globals.css` 据此派生 `--safe-b`（底，保底 12px）、`--safe-l` / `--safe-r`（左右，不保底）与 `--tabbar-h`（= `56px + --safe-b`）。凡是贴边的东西都用这几个变量，不要写死 `bottom-[72px]`、`right-4` 这类数字：
  - 内容区底部留白 `--tabbar-h + 32px`；
  - 悬浮「+ 发布」按钮与需求详情的吸底按钮 `bottom: --tabbar-h + 16px`；
  - 从底部弹出的面板底部内边距 `24px + --safe-b`。

  微信内置浏览器是主要落地场景，iPhone 的小黑条会盖住最下面一截——少了这一步，Tab 栏和吸底按钮都按不准。

  **`fixed` 元素要自己垫左右安全区。** `body` 上的 `--safe-l` / `--safe-r` 内边距只管得住文档流；`fixed` 相对视口定位，吃不到。目前有两个：底部 Tab 栏（`pl/pr-[var(--safe-*)]`）和悬浮「+ 发布」按钮（`right-[calc(16px+var(--safe-r))]`）。横屏进微信时，刘海就在屏幕侧边，漏一个就压住一个。

## 7. 交付自检

1. 这一屏的焦橙是否只有一处主控件，其余橙色都在「微型橙色指示」清单内？
2. 有没有任何纯装饰元素（图形、阴影、渐变、第二种颜色）？
3. 所有间距是否都落在 8pt 网格上？
4. 技术性内容是否都用了等宽字体？
5. 字号是否都取自「字号阶梯」那张表（`text-xl` / `base` / `sm` / `xs` / `2xs` / `3xs`），没有新写死的 px？
6. 承载动作的按钮是否都是 44px（40px 只给搜索框与切换器）？贴边的东西是否都走了 `--tabbar-h` / `--safe-b` / `--safe-l` / `--safe-r`，`fixed` 元素有没有漏垫左右？
7. 可复用控件是否使用 `components/ui/` 中的 shadcn 实现，是否还存在可见原生下拉框、日期选择器或手写弹窗？拼接时有没有拿两个工具类去盖同一个属性？
8. 提示信息是否都是「普通面板 + 6px 状态灯」，没有橙边框、警示三角或感叹号图标？表单错误是否都是单行 `text-accent`？

## 8. 产品验证阶段的补充约定

- 广场按每页 20 条分页，计数取完整筛选结果。清除筛选与发布入口属于空状态的必要出路。
- 首次发布在当前表单补齐一项联系方式；说明默认接受后交换，不能覆盖已有联系方式或隐藏设置。
- 写作提纲只在描述为空时插入；浏览器草稿恢复必须由用户选择，不覆盖当前输入。
- 自己的开放需求详情展示最多三位不同发布者的候选，说明共同标签或暂无共同标签，不展示虚构匹配分数。候选卡与无结果引导沿用已有控件和颜色。
- 连接邮件开关位于设置，使用 shadcn `Switch`，关闭状态与暂未配置邮件通道均明确展示。
- 新增行为与验证口径详见 [PRODUCT-VALIDATION.md](PRODUCT-VALIDATION.md)。


## 9. shadcn 表单与弹层约束

- Select 必须保留 `name`、受控/默认值、标签和 disabled / required 行为。后台筛选仍通过 GET 表单提交；不能只改变显示文字而丢失表单值。
- 日期使用 Calendar + Popover，小时和分钟使用 Select；保持原有本地时间到 ISO 的转换，不改截止时间含义。
- InputOTP 保持数字/字母过滤、粘贴和自动填充；邀请码仍自动大写。
- Dialog / AlertDialog 使用 Portal、Trigger 和对应标题/说明。提交按钮所在表单必须一起放进 Portal，避免按钮脱离原来的表单后失效。破坏性确认保留等待状态与服务端校验，不用自动关闭掩盖失败。
- 框架组件内部为表单语义生成的隐藏 input / select 不作为可见原生控件；禁止为了消除这些内部节点破坏可访问性和提交行为。

- 使用 React Action 的全受控表单须拦截原生 reset（含事件传播），避免 Radix Select 的重置监听把已保存值退回初始值。必须验证连续两次保存，不只检查首次写库成功。
