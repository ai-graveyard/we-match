# We Match 设计规范

风格：**Braun / Dieter Rams**（迪特·拉姆斯风）。严格网格系统，功能即形式，少即是多——每个元素都要有存在的理由，没有一个像素是装饰。

> 本文默认描述**线上已实现**的形态。标了 🚧 **M6** 的条目是连接制（联系方式改为举手被接受后才交换）落地时才成立的规范，现在照着改会跟代码对不上——它依赖 `connected` 可见性档、`contact_reveals` 表和额度体系，这些都还没有。范围见 [PRD.md](PRD.md) 第 8 节 M6 一行。

## 1. 设计令牌

实现时按此定义 CSS 变量（Tailwind 4 的 `@theme`），**十六进制值不得偏移**：

```css
:root {
  --u: 8px;           /* 8pt 网格基准，所有间距为其倍数（允许 4px 半格） */
  --bg: #F7F7F7;      /* 页面背景 */
  --bg-2: #EFEFEF;    /* 次级底色 */
  --bg-3: #ECECEC;    /* 悬停 / 按压 / 选中底色 */
  --panel: #FFFFFF;   /* 面板：卡片、表单、Tab 栏 */
  --ink: #1A1A1A;     /* 正文、主控件 */
  --gray: #808080;    /* 次要文字 */
  --line: #C9C9C9;    /* 分隔线、边框（1px） */
  --accent: #E8500A;  /* 焦橙——唯一强调色，只给功能性控件 */
  --sans: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
          "Helvetica Neue", Arial, "PingFang SC", "Microsoft YaHei", sans-serif;
  --mono: ui-monospace, "SF Mono", Menlo, Consolas, monospace;
}
```

暗色主题通过 `<html data-theme="dark">` 覆盖以下令牌（同样**不得偏移**）；`--accent` 是品牌常量，明暗一致。切换入口：桌面端顶部导航图标按钮，移动端「我的 → 设置」的「明暗主题」行；偏好存 `localStorage`，无记录时跟随系统：

```css
[data-theme="dark"] {
  --bg: #121212;
  --bg-2: #1A1A1A;
  --bg-3: #2A2A2A;
  --panel: #1C1C1C;
  --ink: #EDEDED;
  --gray: #9A9A9A;
  --line: #333333;
}
```

- 圆角：小控件 8px，面板 12px，**不超过 12px**。
- 分隔一律用 1px `--line`，**不用阴影**。
- **字号阶梯**（按微信小程序 / WeUI 与 iOS HIG 的手机端惯例定档）。每一档都有对应的工具类，**组件里不写 `text-[12px]` 这类任意值**——写死的没法统一调，整套界面只在 `app/globals.css` 的 `@theme` 里换档：

  | 角色 | 字号 | Tailwind |
  |------|------|----------|
  | 页面标题 | 20px / 600 | `text-xl` |
  | 加大正文（姓名、组织名、验证码格） | 17px | `text-base` |
  | 正文、描述、按钮 | 15px / 行高 1.5 | `text-sm` |
  | 次要说明 | 13px | `text-xs` |
  | 辅助文字（等宽元信息、标签、状态、计数、小节标签） | 12px | `text-2xs` |
  | 徽章等极小注记（**下限，不得再小**） | 11px | `text-3xs` |

  `2xs` / `3xs` 是本项目在 Tailwind 自带阶梯下方补的两档，刻意不配 `--text-*--line-height`，行高继承 body 的 1.5——它们只用在单行元信息上，配了行高反而把紧凑表格撑开。

  两处例外，不受这张表约束：**分享图**（`components/share-card.tsx` 的 `Poster`）是导出成 PNG 的固定画布，字号颜色一律写死；**管理后台**（`app/admin`）是内部工具，表格密度优先。

## 2. 品牌标识

标识是 **W 与 M 拧成的双股波线**：墨色一条是 w（随 `--ink` 明暗切换），焦橙一条是 m（`--accent`，品牌常量）。两条线拧一圈半，三处交叉的上下关系交替（橙上、墨上、橙上），像互相咬住的双股弹簧；整个图形 180° 旋转对称——转过来仍是自己，即 "we match" 的含义。

- **唯一实现源**：路径数据与 `LogoMark`、`LogoSpinner` 在 `components/logo.tsx`（保持服务端可渲染），带悬停动画的 `Brand`（标识与字标组合）在 `components/brand.tsx`；SVG 路径数据不得改动、不得目测重画。
- **favicon**：`app/icon.svg`，焦橙圆角方块（圆角 52/240）上白、墨双线；为小尺寸清晰，线宽 18（组件内为 15），是唯一允许的偏差。
- **应用图标**：`app/apple-icon.tsx` 复用 `icon.svg` 铺满焦橙底输出 180×180 PNG（圆角交给 iOS 遮罩）；`app/manifest.ts` 的图标指向 `/icon.svg`。
- **字标**：「We Match」15px / 700 / 字距 -0.02em（大小写混排，不用全大写字距），与标识间距 8px。`Brand` 只有两档：`sm`（标识 16 / 字标 15，默认）与 `lg`（标识 28 / 字标 26，仅登录页），不得随手缩放。
- **品牌口号**：「让合适的人碰面」。桌面顶部导航放在字标右侧，登录页放在大号字标下方，「我的 → 用户」页脚和分享海报使用同一句；OG 图因默认字体不含中文，使用对应英文 `LET THE RIGHT PEOPLE MEET`。其他位置不另写近义口号。
- **单色档**（`LogoMark` 的 `muted`）：两股都走 `currentColor`。只用于列表终点标记、空状态这类「非品牌焦点」的位置，配 `--line`；目的是让标识出现在这些地方时不把焦橙一起带过去。带色的完整标识留给顶部导航、登录页、「我的」页脚、分享海报和 OG 图。
- **加载指示**（`LogoSpinner`）：螺纹旋转——编织图案沿轴向匀速平移，每 1.6s 移动一个波长（`linear` 循环），侧视投影上等效于双股螺旋绕水平轴转动，如螺杆旋进；用于路由级 `loading.tsx`；`prefers-reduced-motion` 下随全局规则静止。
- **禁止**：拉伸变形、改成单色档以外的颜色、加投影、给标识做大面积橙底（应用图标除外）。
- 使用位置：桌面顶部导航、登录页、管理后台头部、品牌页脚（以上用 `Brand`，不手写）；列表终点与空状态（`ListEnd` / `EmptyState`，单色档）；分享海报头部；`app/opengraph-image.tsx`。

## 3. 焦橙纪律（最重要的一条）

**每个界面最多出现一处焦橙主控件**，给当前界面的核心功能控件：

| 界面 | 焦橙给谁 |
|------|----------|
| 广场（需求流） | 「+ 发布」按钮 |
| 发布/编辑需求 | 提交按钮 |
| 需求详情 | 唯一的意图按钮（「我能提供 / 我想了解」，已举手后转为「查看联系方式」）；面板打开后转移给举手表单的提交按钮，连接后转移给交换到的渠道动作，等待回应时面板内不留焦橙 |
| 收到的举手 | 「接受」按钮（「拒绝」为墨色次按钮，但两者点击代价必须相当，见「举手与连接」） |
| 用户名片 | 已登录时为「复制」联系方式按钮；未登录时为「登录后查看」按钮 |
| 组织广场 | 「凭邀请码申请」提交按钮 |
| 组织详情（非成员视角） | 「申请加入」按钮 |
| 组织详情（owner 视角） | 「复制邀请码」按钮（admin / member 视角无焦橙，允许） |
| 编辑名片 | 保存按钮 |
| 登录 | 「获取验证码 / 登录」按钮 |

在主控件之外，允许且仅允许以下三种**微型橙色指示**（对应 Braun 硬件上的电源点 / 档位指针 / 指示灯，不计入上表）：

1. **品牌标识**：logo 双股波线中的焦橙一股（顶部导航、登录页、管理后台、「我的 → 用户」页脚、路由加载指示，见「品牌标识」一节）。列表终点与空状态里的标识一律走单色档，不带这股橙；
2. **Tab 当前项**：底部 Tab 栏 / 桌面顶部导航保持纯文字，当前项文字转 `--accent` 加粗；导航不使用图标；
3. **状态灯**：6px 焦橙圆点，只用来标记「有一件事此刻成立」，两处：
   - 广场搜索筛选区下方合并展示计数与筛选入口，右对齐；默认为「N 条进行中 · 显示全部」，切换后为「N 条 · 只看进行中」；圆点仅在「进行中」状态亮起；
   - 需要用户留意但不构成动作的系统提示（如登录页「短信通道未开通」），普通面板 + 墨色标题 + `--gray` 说明，圆点置于标题行首。

其余一切控件黑白灰。徽章、标签（tag）、分段控件、输入框 focus 态一律不用橙；焦橙不做大面积底色（主按钮除外）、不做装饰图形。出现清单之外的焦橙即违规——多了就成了装饰。

**提示类信息不用警示框。** 橙色边框、警示三角、感叹号图标都是清单外的装饰，而且会跟同屏的焦橙主按钮抢注意力——用户在登录页真正要点的是「登录」。提示要被看见，靠的是位置（紧贴相关控件）和一个 6px 的点，不是加粗边框。表单校验错误另有约定：沿用 `text-accent` 单行文案，不加边框和图标。

## 4. 字体分工

- **等宽（`--mono`）用于一切技术性内容**：标签（tag）、时间戳、邀请码、计数、需求状态、手机号显示。
- **无衬线（`--sans`）用于正文**：标题、描述、昵称、按钮文字。
- 小节标签（如组织主页的「需求 / 成员 / 设置」分段头）：12px / 600 / 字距 0.08em / `--gray`；英文内容全大写。字距只留给这类标签和按钮，正文不加。

## 5. 组件规范

- **底部 Tab 栏（移动端）**：内容高 56px，下方另垫 `env(safe-area-inset-bottom)`，`--panel` 底 + 顶部 1px `--line`；文字 16–17px（`text-base`）；2 项（广场 / 我的），只显示文字、不使用图标；当前项 `--accent` 加粗（见焦橙纪律之「微型橙色指示」），非当前项 `--gray`。桌面端（≥768px）换为顶部导航条：高 64px，底部 1px `--line`，同样保持纯文字导航。
- **范围切换器（广场页顶部，仅登录后显示）**：与「我的」页顶部菜单保持一致，横向纯文字排列并可滚动；当前范围放大为 20px / 600、文字转 `--accent`，其他范围为 15px `--gray`；组织名最多 10 字，菜单项须为完整 10 字预留空间，不得裁切选中态；末尾固定纯图标「+」入口进入组织广场。切换范围时保留当前类型、搜索、标签和开放状态筛选。
- **广场搜索**：搜索框右侧内嵌带分隔线的放大镜提交按钮，同时支持 Enter 提交；按钮必须提供「搜索」无障碍名称，不能把放大镜作为输入框内的纯装饰。
- **供需类型筛选**：移动端使用「全 / 需 / 供」为搜索框保留空间，桌面端显示完整的「全部 / 需要 / 提供」；短标签仍须提供完整的无障碍名称。
- **组织概览卡（我的页）**：每个组织独立成卡，不把多个组织压在同一张列表卡里；卡内展示成员、开放需求与待审批摘要，底部按角色直接提供需求、成员、审批、邀请入口。创建与发现组织拆为卡片外的并列动作。组织详情页顶部用横向 chip 提供同样的区块直达入口，避免依赖长页滚动发现功能。
- **列表行**：`--panel` 底，行内边距 16px，行高 ≥ 48px，行间 1px `--line`；悬停/按压背景 `--bg-3`，过渡 `.12s linear`。
- **按钮**：15px / 600 / 字距 0.06em，高 44px（`h-11`，iOS 最小点击尺寸；小程序主按钮普遍 16px / 44–48px 高，15px 是配合本项目 Braun 底子的下沿）；主按钮（每屏唯一，即该屏的焦橙控件）`--accent` 底白字，次按钮 `--panel` 底 + 1px `--ink` 边框（悬停反色 `--ink` 底白字）；按压位移 `translateY(1px)`。**一切承载动作的按钮都是 44px**，不分主次、不分弹窗内外——32px 甚至 36px 的按钮手指按不准。
- **40px（`h-10`）只留给三类不承载动作的控件**：搜索框、范围/分类切换器（广场页顶部、「我的」页顶部）、分段控件（名片对外预览）。它们要么是输入，要么是在同级选项间切换，误点代价接近零，密度比手指余量更重要。管理后台（`app/admin`）整体不适用本条。
- **输入框**：高 44px（与按钮同高，同一行里才不会错位；搜索框按上一条用 40px），`--panel` 底 + 1px `--line` 边框 + 8px 圆角，focus 时边框转 `--ink`（不用橙）。
- **分段控件**（类型筛选、可见范围三态）：1px `--line` 外框，选中段 `--ink` 底白字，未选中 `--gray` 字。
- **标签（tag）**：`--mono` 12px，1px `--line` 边框 + 8px 圆角，`--gray` 字；选中态边框和文字转 `--ink`。
- **默认头像**：正方形 + 8px 圆角（不用圆形），`--bg-3` 底，使用灰色 Lucide `UserRound` 图标；MVP 不做头像上传。
- **空状态**（`EmptyState`）：单色档标识（高 22，`--line`）+ 一行 `--gray` 文字，居中；需要时文字里带一个行内动作链接。不配插图。
- **列表终点**（`ListEnd`）：列表滚完后居中一个单色档标识（高 12，`--line`），上下留白 32px，代替「没有更多了」这类文案。只给整页主列表用，不给卡内嵌套的子列表用。
- **品牌页脚**（`BrandFooter`）：1px `--line` 分隔线 + 居中 `Brand` + 标语，不放别的——用户协议、隐私政策和版本号都在「我的 → 设置」。**仅移动端**——桌面端顶部导航条已有字标，再放页脚是重复。只出现在两处：广场页「广场」范围的列表末尾（切到组织范围不放），以及「我的 → 用户」末尾（组织 / 需求 / Agent / 设置不放）。广场这两处由页脚兼任列表终点，桌面端则退回 `ListEnd`（`desktopOnly`）。
- **名片联系方式锁定态**（都不使用锁图标、星号打码或字段占位行，都不透露字段类型与数量）：
  - **匿名访客**（已实现）：不渲染任何联系方式或社媒原值。用一个普通面板提示登录，下方放唯一焦橙主按钮“登录后查看”，登录后回跳原名片。
  - 🚧 **M6** —— **已登录但未连接**：社媒正常显示；联系方式区域用同款普通面板提示“联系方式在对方接受你的举手后交换”，下方不放按钮——**要举手得去具体的需求上举**，名片页没有可举手的对象，放按钮只会把人带到死路。若对方有开放需求，面板里给一行文字链接指向 TA 的需求列表。
  - 🚧 **M6** —— **已连接**：只显示这次交换到的那一项，旁边标注来自哪条需求（`--mono` 12px `--gray`）。名片上的其他联系方式仍然不显示——连接是那条需求上的一次交换，不是把整张名片打开。

    M6 前只有匿名 / 已登录两态，登录后按 `authenticated` / `orgs` 直接渲染，匿名提示文案也相应写的是“联系方式与社媒”。
- **需求快捷联系**：开放且未过期的他人需求在详情页提供**一个**全宽意图按钮。举手和联系是同一个入口的两种状态，**不并列成两个按钮**——并列过一次，两个按钮的文案都是「我能提供」，用户分不清点哪个，页面上还同时出现了两处焦橙。移动端按钮停靠在底部 Tab 上方。面板移动端从底部出现、桌面端居中，必须明确显示需求标题。面板内容随举手状态切换：
  - **未举手 / 被拒 / 已撤回**：按钮是「我能提供 / 我想了解」，面板内是举手表单（留言框 + 提交按钮，提交按钮是唯一焦橙动作）。🚧 **M6** 时表单里再加一个自己的联系方式选择器，作为交换物。
  - **等待回应**：按钮转为「查看联系方式」，面板首行交代状态。撤回入口只留在页面的「我的举手」里，不在面板内重复。这一态面板内没有焦橙——此刻没有该用户推进的动作，硬凑一个只会误导。
  - **已连接**：按钮是「查看联系方式」，面板内是快捷联系面板（交换到的那一项独占一张卡和唯一焦橙动作，「复制开场白」用墨色次按钮）。
  - 对方没有任何可见渠道时，按钮仍然出现（面板内只有举手表单）——举手本来就不依赖看得见联系方式。反过来，已举手且无渠道可看时不留空入口。

  微信号复制、手机号 `tel:` 拨打、邮箱 `mailto:` 预填，不实现站内私信。

  **M6 前的过渡**：联系方式还停在`登录可见`档，所以未连接时面板里在举手表单下方还有一段「也可以直接联系」（墨色次按钮，不抢焦橙）。M6 收紧权限后删掉这段。在那之前不能提前藏——名片页此时照样看得到，详情页单方面藏起来只会让人以为坏了，还假装给了一个并不存在的保护。
- **举手与连接**：
  - 🚧 **M6** —— 举手表单里的交换预告是**规范要求，不是可选文案**：紧贴联系方式选择器下方一行 `--gray` 12px，写明「接受后对方将看到你的微信号」。用户必须在点提交之前就知道自己给出去什么。
  - 收到的举手：**「接受」与「拒绝」的点击代价必须相当**——同一行、同样尺寸、都不要二次确认。接受是焦橙主按钮，拒绝是墨色次按钮，但绝不能把拒绝藏进折叠菜单或多加一步。发布者一旦觉得拒绝麻烦，就会转向不理会，而不理会是对举手方最差的结果（白等 72 小时）。
  - 举手状态用 `--mono` 12px：`等待回应` / `已连接` / `未接受` / `已撤回`。状态不用颜色区分，只用文字——这里出现第二种颜色就破了焦橙纪律。
  - 🚧 **M6** —— 增加第五个状态「已无回应」：72 小时无人处理的 pending，文案要中性，不暗示对方失礼。
- **本人对外预览**：名片顶部使用现有分段控件展示`未登录访客 / 已登录用户 / 共同组织成员`三档；选中态墨底白字，不使用焦橙。预览说明与“编辑名片”入口置于分段控件下方。
  - **不设「已连接」档**。预览回答的是「别人看我的名片是什么样」，而连接只在那条需求、那一项字段上成立（见 [PRD.md](PRD.md) 5「已连接不是一种身份，是一段关系」）——脱离具体需求就答不出该显示哪一项：挑一项当示例是瞎猜，把所有`连接后可见`字段都列出来又变成了「我的可见性设置」，那是编辑名片页的事。前三档是身份，给定访问者即可判定；连接是事件，塞进身份切换器只能靠改口径糊过去。
  - 🚧 **M6** —— `连接后可见`的字段在这三档下一律不显示，改由预览说明条上一行 `--gray` 12px 交代，如「另有 2 项联系方式要在具体需求上接受举手后才交换」。这行只有本人看得到，比一个档位更能讲清「逐条需求、逐项交换」。
  - 这不影响**访问者**视角：已与本人连接的人打开名片时，照常按上面「名片联系方式锁定态」的第三条渲染（那时「哪条需求」是明确的）。去掉的只是本人自己切过去看的入口。
- 🚧 **M6** —— **额度提示**（整节尚未实现，额度体系本身也还没有代码，见 [QUOTA.md](QUOTA.md)）：额度是规则，不是惩罚，所以呈现要克制。
  - 计数一律 `--mono` 12px `--gray`，**不用焦橙**——焦橙留给当屏主控件，额度提示挤进来就成了装饰。
  - **平时不显示**：发布按钮、举手表单旁的剩余计数只在剩余 ≤ 3 时出现，形如 `剩余 2 / 8`。天天顶着计数器会诱导用户去想怎么把额度用完。
  - 三处常驻例外，因为它们是需要用户主动管理的：举手表单底部的 `3 个等待回应中 · 还能举手 4 次`、举手表单里的交换预告、「我的」页顶部未处理举手 ≥ 5 时的 `8 个举手等你处理`。
  - **撞墙文案必须带出路**：每条限制都配一个具体的下一步和直达链接，不能只说“已达上限”。完整文案表见 [QUOTA.md](QUOTA.md) 第 11 节。
  - 撞墙提示沿用现有表单错误样式（`text-accent`），不为额度新增颜色或图标。
- **动效**：仅入场渐显（上移 8px，`.5s ease-out`）、控件过渡（`.12s linear`）与路由加载的品牌标识旋转（见「品牌标识」）；`prefers-reduced-motion` 时全部关闭。

## 6. 布局

- 内容区最大宽度 640px，桌面端居中；页面左右内边距：移动端 16px，桌面端 32px。
- 所有间距取 8 的倍数（4px 半格允许）；一处错位全盘皆输。
- **移动端安全区**：`app/layout.tsx` 声明 `viewportFit: "cover"`，`globals.css` 据此派生 `--safe-b`（底，保底 12px）、`--safe-l` / `--safe-r`（左右，不保底）与 `--tabbar-h`（= `56px + --safe-b`）。凡是贴边的东西都用这几个变量，不要写死 `bottom-[72px]`、`right-4` 这类数字：
  - 内容区底部留白 `--tabbar-h + 32px`；
  - 悬浮「+ 发布」按钮与需求详情的吸底按钮 `bottom: --tabbar-h + 16px`；
  - 从底部弹出的面板底部内边距 `24px + --safe-b`。

  微信内置浏览器是主要落地场景，iPhone 的小黑条会盖住最下面一截——少了这一步，Tab 栏和吸底按钮都按不准。

  **`fixed` 元素要自己垫左右安全区。** `body` 上的 `--safe-l` / `--safe-r` 内边距只管得住文档流；`fixed` 相对视口定位，吃不到。目前有两个：底部 Tab 栏（`pl/pr-[var(--safe-*)]`）和悬浮「+ 发布」按钮（`right-[calc(16px+var(--safe-r))]`）。横屏进微信时，刘海就在屏幕侧边，漏一个就压住一个。

4. 技术性内容是否都用了等宽字体？
