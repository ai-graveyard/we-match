# We Match 产品需求文档（PRD）

- 版本：v0.9（MVP）
- 日期：2026-08-06
- 状态：待确认

## 1. 产品概述

**一句话描述**：一个极简的供需匹配工具。每个人有一张名片，可以发布"我需要"或"我提供"的需求；需求可以发到公开广场，也可以发到自己加入的组织里；通过浏览、筛选、搜索找到对的人，再从需求详情页用对方开放的渠道快速联系。

**品牌口号**：让合适的人碰面。

**设计原则**：极简。每个功能只保留最小可用形态，能靠约定解决的不做配置，能人工完成的不做自动化。

**界面约束**：全站页面不超过 10 个，主导航固定 2 项（广场 / 我的）；组织不占导航位，以广场页顶部的范围切换呈现；UI 极简风；移动端优先，桌面端其次。

**MVP 明确不做**（见第 8 节）：自动撮合、站内私信、消息通知、头像上传、内容审核。

## 2. 核心概念

| 概念 | 说明 |
|------|------|
| 用户 / 名片 | 一个手机号对应一个用户，每个用户有一张名片；基本资料可公开浏览，联系方式与社媒至少登录后才可见 |
| 需求 | 用户发布的一条供需信息，分「我需要」和「我提供」两个方向 |
| 广场 | 全站公开的需求流，任何访客可见（无需登录） |
| 组织 | 圈子，分「公开」和「私有」。公开组织可在组织广场被发现，申请加入需管理员审批；私有组织不出现在组织广场，凭邀请码加入。组织内的需求仅成员可见 |

## 3. 功能需求

### 3.1 账号与登录

- 手机号 + 短信验证码登录，**无密码**。MVP 仅支持大陆 11 位手机号（国际号段随真实短信通道放二期）。
- 首次登录即自动注册，**注册时自动生成默认昵称**「用户 + 手机尾号 4 位」（如「用户3407」）——保证任何用户在列表、成员、审批场景里都有可显示的名字。
- 验证码规则：6 位数字，5 分钟有效，同一手机号 60 秒内只能发送一次，连续验证失败 5 次后作废。
- 防滥用：除手机号维度外，同一 IP 每小时最多请求 10 次验证码（短信接口接入真实服务商后，这是防刷的底线）。
- 短信通道做成可插拔接口（`SmsProvider`）：
  - **开发/演示环境**：验证码打印到服务端日志，不真实发送。
  - **生产环境**：预留阿里云/腾讯云短信实现，接入前可继续用日志通道。
- 会话：httpOnly cookie session，有效期 30 天，退出登录即失效。
- **账号注销**（「我的 → 设置」内自助，永久且不可恢复）：清空名片资料（昵称改为「已注销用户」）、关闭全部需求、撤回进行中的举手、退出所有组织、吊销全部 API Key 并删除通知与会话；手机号保留在 users 表（`status = deleted`），**从此无法再次登录**。组织 owner 需先解散组织才能注销。**手机号换绑明确不支持。**
- **访问模型：公开内容无需登录，联系方式与社媒不向匿名访客下发。**
  - 未登录可看：广场需求流、公开需求详情、用户名片的公开基本资料与广场需求、组织广场及公开组织的简介页（名称、简介、成员数）。若名片存在“登录可见”的联系方式或社媒，只显示统一的登录提示，不显示字段类型、数量或值。
  - 普通登录用户：在未登录可见内容之外，可查看对方设为“登录可见”的联系方式与社媒。
  - 与对方同属至少一个组织的登录用户：还可查看对方设为“共同组织可见”的联系方式与社媒。
  - 必须登录：发布/编辑需求、编辑名片、创建/申请/加入组织、查看组织内需求与成员列表（仅成员可见）。
  - 未登录点击写操作时跳转登录页，登录后回到原页面。

### 3.2 个人名片

- 字段（除昵称外均为可选）：
  - **基本信息**：昵称（必填，≤ 20 字）、一句话介绍（≤ 100 字）、技能/兴趣标签（最多 10 个，单个 ≤ 20 字）、所在城市
  - **联系方式**：微信号、邮箱、电话
  - **社媒账号**：微信公众号、视频号、小红书、微博（均为自由文本，可填名称或主页链接）
- **逐项可见范围**：名片上每个字段都可以单独设置可见范围。
  - 基本信息字段（介绍、标签、城市）：两态——`公开` / `隐藏`。
  - 联系方式与社媒字段：三态——`登录可见` / `共同组织可见` / `隐藏`。“登录可见”指任意已登录用户可见；“共同组织可见”指访问者与本人同属至少一个组织时可见。MVP 不提供联系方式的“全网公开”档，避免手机号、微信、邮箱和社媒账号进入匿名页面、搜索索引或爬虫数据。
  - 昵称除外——昵称始终公开（需求列表、成员列表都要靠它标识人）。
  - 默认值：基本信息填写即公开；联系方式与社媒填写后默认为`登录可见`。用户可随时调整。
  - 未登录访问名片时，若存在`登录可见`字段，联系方式区域只显示“登录后可查看对方向已登录用户开放的联系方式与社媒”及登录按钮，登录后回跳原名片；原值必须在服务端过滤，不得通过 HTML、RSC 数据、接口响应或仅靠 CSS/星号遮罩泄露。
  - `共同组织可见`和`隐藏`字段对不满足条件的访问者完全不显示，也不通过锁定提示暴露字段类型或数量；仅本人在“我的/编辑名片”可见全部原值。
- 联系方式与社媒字段展示时支持**一键复制**（微信号靠手抄必然出错）。
- 技能标签输入时**联想已有标签**，优先复用（与需求标签共用词库），避免"前端 / 写代码 / web开发"各写各的导致筛选失效。
- 头像：MVP 不做文件上传，统一使用 Lucide `UserRound` 默认头像。
- 首次登录后引导修改昵称（注册时已生成默认昵称，见 3.1；其余字段可跳过）。
- **保存名片时的可联系性提醒**：若本人有「开放」状态的需求，而这次保存后名片上已无任何该需求受众可见的联系方式（广场需求对应无`登录可见`项、组织需求对应无`登录可见`或`共同组织可见`项），给一条**非阻断提醒**——不禁止保存（用户有权改自己的名片），发布时的强校验见 3.3。
- 名片页无需登录即可打开，但匿名访客只看到公开基本资料、登录提示和广场需求；入口：需求详情页的发布者、组织成员列表。名片页附带的需求列表**仅含其广场公开需求**（组织内需求去广场页切范围查看）。本人从“我的”进入对外预览时，可切换`未登录访客` / `已登录用户` / `共同组织成员`三种视角；该切换仅控制预览，不改变权限或数据。

### 3.3 需求

- 字段：
  - 类型（必填）：`我需要` / `我提供`
  - 标题（必填，≤ 50 字）
  - 详细描述（可选，≤ 2000 字）
  - 标签（可选，最多 10 个，单个 ≤ 20 字，输入时联想已有标签）
  - 截止时间（必填）：可选具体日期时间，快捷项为 `1 天` / `3 天` / `7 天` / `1 个月` / `永久`，默认 `1 个月`
  - 可见范围（必填）：`广场公开` 或 指定某个自己已加入的组织（单选，一条需求只属于一个范围）。**发布后不可修改**——要改范围，关闭原需求后重新发布，避免广场↔组织互转牵出的校验连环。
  - 优先联系方式（必填）：从本人名片上对该需求受众可见的微信号、邮箱、手机号中选择一项。广场需求只能选`登录可见`项；组织需求可额外选择`共同组织可见`项。旧需求未记录时按微信、邮箱、手机号的顺序自动回退到第一项可见渠道。
  - 状态：`开放` / `已完成` / `已关闭`，默认开放
- 操作：发布、编辑（不含可见范围）、变更状态、删除（仅发布者本人）。
- **发布前的可联系性校验**：发广场需求要求名片上至少有一项`登录可见`的联系方式；发组织需求要求至少有一项`登录可见`或`共同组织可见`的联系方式。不满足则阻断发布并引导去名片开启——否则需求发出去也没人联系得上。
- **截止与续期**：`开放`状态的需求超过用户选择的 `expires_at` 即显示为`已过期`，并默认从列表隐藏；`expires_at = NULL` 表示永久有效。发布者可编辑具体截止时间，或点「续期一个月」快速恢复。编辑其他内容不会偷偷改变截止时间。
- 频率限制：每用户每天最多发布 10 条需求。
- 列表与匹配（人工匹配）：
  - 广场页：全部公开需求，时间倒序。
  - 组织页：该组织内的需求，时间倒序。
  - 两处均支持：按类型筛选（需要/提供）、按标签筛选、关键词搜索（匹配标题和描述）。
  - 默认只显示「开放」且未过期的需求，可切换查看全部。
- 需求详情页：完整内容 + 发布者名片入口 + 意图化联系按钮。「我需要」显示「我能提供」，「我提供」显示「我想了解」；仅开放且未过期的他人需求显示。
- **快捷联系面板**：优先展示发布者为该需求选择的渠道，其余可见联系方式作为备选；微信号一键复制、手机号直接拨打、邮箱打开邮件客户端并预填主题与正文。面板同时生成一段带需求标题的可编辑联系开场白，支持一键复制。
- **登录回跳**：匿名访客点击联系按钮后进入登录，成功后回到原需求并自动打开联系面板；联系方式原值仍只在服务端确认权限后下发。
- **组织内需求的详情页对非成员返回 404**（连"存在但无权"都不暴露）；微信分享 OG 预览也只对广场公开需求生效。

### 3.4 组织

- 创建：任何用户可创建组织，填写名称（必填，≤ 10 字）、简介（可选，≤ 500 字）、类型（必填：`公开` / `私有`，默认私有，owner 可随时切换）。创建者即唯一 owner；owner 自身拥有管理员权限，但不占任命名额。每个组织最多另设 3 名 admin，owner 和现有 admin 都可以把普通成员任命为 admin。
- 组织从公开切为私有时，已有的广场来源待审申请**保留**，管理员照常处理，不自动作废。
- 加入方式（两条路径，**均需管理员审批**）：
  - **邀请码申请**（公开、私有组织都可用；私有组织的唯一入口）：创建时自动生成 8 位邀请码——大写字母 + 数字随机组合，剔除易混淆的 `0/O/1/I`，校验时不区分大小写；仅 owner 可查看和重置（重置后旧码立即失效）。owner 把邀请码（或含码的邀请链接）发给对方，对方输入正确的邀请码后提交申请。防穷举：同一用户输错邀请码每小时最多 10 次。
  - **组织广场申请**（仅公开组织）：登录用户在组织广场看到公开组织，点「申请加入」提交申请。
  - 两条路径汇入同一张待审批列表（标注来源：邀请码 / 广场），任一管理员均可逐条通过或拒绝，通过后成为成员。同一组织有待审批申请时不能重复申请；被拒绝后可再次申请。
- 组织广场：全部公开组织的列表（名称、简介、成员数），支持名称关键词搜索，创建时间倒序；私有组织不出现。
- 角色（三类，owner 唯一、拥有全部管理员权限并在 3 名 admin 名额之外）：
  - **owner**：拥有 admin 的全部权限，并可编辑组织资料、切换公开/私有、查看/重置邀请码、移除成员、解散组织。
  - **admin**：任命其他普通成员为 admin（总数不超过 3 人）、审批加入申请；同时拥有普通成员权限。
  - **member**：查看组织内需求和成员列表、在组织内发需求、退出组织。
- 组织详情页双视角：
  - **非成员**（仅公开组织可达，私有组织对非成员不可见）：名称、简介、成员数、「申请加入」按钮；看不到成员列表和组织内需求。
  - **成员**：简介 + 成员列表（点成员看名片；支持**按技能标签筛选**和昵称搜索——按"人的能力"找人，与按需求找人互补）+ 退出组织；admin 额外可见管理员任命和待审批申请，owner 额外可见资料编辑、类型切换、邀请码、移除成员、解散。
  - 组织内需求流不在详情页，在广场页顶部切换范围查看（见 4.1）。
- **退出 / 被移除的连带处理**：该成员发布在该组织内的需求自动置为「已关闭」（仍保留在其「我的需求」里，可自行改发广场）——避免组织里挂着发布者已联系不上的僵尸需求。被移除者可立即重新申请，MVP 无黑名单（见第 8 节），审批本身就是关卡。
- 解散组织：组织内需求、成员关系、待审批申请一并删除，需二次确认。
- owner 不能直接退出组织（避免组织悬空），只能解散；admin 可以像普通成员一样退出；暂不支持转让 owner。
- **一个用户最多同时加入 3 个组织**（自己创建的也计入）。已满 3 个时不能再创建组织、提交申请或凭邀请码加入；管理员审批通过时若申请人已满额，则通过失败并提示。退出或组织解散后名额释放。
- 申请中的组织在「我的」页显示「申请中」状态（申请中不占名额，入会时才校验）。

### 3.5 我的

- 编辑自己的名片。
- 我的需求列表（含广场和各组织的），可管理状态。
- 我的组织概览卡（含成员数、开放需求数、待审批数与「申请中」状态），卡片直接提供需求、成员、审批、邀请等角色对应的高频入口；入口：创建组织（进入独立创建页）、去组织广场（发现公开组织 / 凭邀请码加入）。
- 退出登录。

## 4. 页面结构与导航

### 4.1 导航（2 项 + 范围切换，不再增加）

- 主导航固定 2 项：**广场**（`/`）、**我的**（`/me`）。移动端为底部 Tab 栏，桌面端为顶部导航条，同一组件响应式切换。
- **范围切换**：广场页顶部提供范围切换（`广场` / 各个已加入的组织），组织内需求流与广场共用同一页面，只是数据范围不同。
  - 登录后切换器始终显示，横向排列（组织多时可横向滚动），末尾「+」进入组织广场；未登录不显示切换器——广场就是唯一范围。
  - 切到某组织时，页头显示组织名，点组织名进入组织详情页（成员/设置）。
- **组织广场**（`/orgs`）：发现公开组织 + 凭邀请码加入（页顶输入框），入口：切换器末尾「+」、「我的」页。
- 「创建组织」入口固定在「我的」页（保证没组织的用户也找得到），点击后进入独立创建页，可保存或返回。
- 发布需求不占导航位：广场页内放「+ 发布」按钮，可见范围默认取当前切换的范围。
- 其余页面均为二级页，靠页内返回/浏览器后退退出，不进导航。

## 5. 权限矩阵

| 行为 | 未登录 | 登录用户 | 组织成员 | 组织 admin | 组织 owner |
|------|--------|----------|----------|------------|------------|

## 6. 数据模型草案

```
users               id, phone(唯一, 登录用), nickname, bio, tags(JSON), city,
                    wechat, email, contact_phone,
                    weixin_mp(公众号), weixin_channels(视频号), xiaohongshu, weibo,
                    field_visibility(JSON 对象；基本资料 public|hidden，联系方式 authenticated|orgs|hidden), created_at
verification_codes  id, phone, code, ip, expires_at, fail_count, created_at
sessions            id(token), user_id, expires_at, created_at
needs               id, user_id, type(need|offer), title, description, tags(JSON),
                    preferred_contact(wechat|email|contactPhone),
                    org_id(NULL=广场), status(open|done|closed), expires_at(NULL=永久),
                    created_at, updated_at
orgs                id, name, description, visibility(public|private), owner_id,
                    invite_code(全局唯一), created_at
org_members         org_id, user_id, role(owner|admin|member), joined_at
join_requests       id, org_id, user_id, via(code|plaza),
                    status(pending|approved|rejected), created_at, handled_at
```

- 标签用 JSON 数组存储，筛选用 LIKE 匹配，MVP 数据量下足够。
- `join_requests` 同一 `(org_id, user_id)` 至多一条 `pending`；通过时写入 `org_members` 并更新状态；解散组织时连带删除。
- `needs.org_id` 为空即广场公开，非空即组织内可见——一个字段承载可见范围。
- 可见性用 `field_visibility` 一个 JSON 对象实现（如 `{"email": "orgs", "weibo": "hidden"}`）。基本资料未记录时默认`public`；联系方式与社媒未记录时默认`authenticated`。渲染他人视角的名片时：基本资料的`public`可匿名显示；敏感字段的`authenticated`要求登录，`orgs`还要检查访问者与主人是否同属至少一个组织，`hidden`始终过滤。升级时历史敏感字段的缺省值或旧`public`值一律按`authenticated`解释，不继续全网公开。登录手机号 `phone` 仅用于认证，任何情况下都不对外展示。
- 需求截止时间落在 `expires_at`；`NULL` 表示永久，过期仍由查询/渲染实时判断，无定时任务。

## 7. 技术方案

- **框架**：Next.js 16 App Router 前后端一体（Server Components + Server Actions；具体 API 以 `node_modules/next/dist/docs/` 内的当前版本文档为准）。
- **数据库**：SQLite 单文件 + Drizzle ORM（better-sqlite3 驱动），零外部服务。
- **认证**：自实现。验证码表 + session 表 + signed httpOnly cookie，不引入第三方认证库。
- **短信**：`SmsProvider` 接口 + 日志实现（dev），生产接入留待二期。
- **UI**：Tailwind CSS 4。视觉风格为 **Braun / Dieter Rams**：浅暖灰底（#F7F7F7 / #EFEFEF / #ECECEC）+ 白色面板，唯一强调色焦橙 #E8500A 每屏至多一处、只给功能性控件；等宽字体用于技术标签，圆角 2–4px，严格 8pt 网格，完整规范见 `docs/DESIGN.md`。移动端优先（此类工具主要在手机上用），内容区最大宽度 640px，桌面端居中窄栏布局，同一套页面自适应两端，不做独立桌面版。
- **部署**：`next start` 自部署（本机 / VPS / Docker），SQLite 文件放持久化目录。不适配 Vercel serverless。

## 9. 里程碑

| 阶段 | 内容 | 验收标准 |
|------|------|----------|
| M1 | 项目骨架、数据库、手机号验证码登录 | 能注册登录，session 持久有效 |
| M2 | 名片：填写、编辑、查看、逐项可见范围、一键复制 | 未登录访客不收到敏感原值；登录用户可见`登录可见`字段；隐藏正确生效（`共同组织可见`随 M4 联调验收） |
| M3 | 需求：发布（含可联系性校验）、广场流、筛选、搜索、详情、自选截止时间与续期、标签联想 | 广场完整可用，可通过名片联系到人，过期需求可续期 |
| M4 | 组织：创建（公开/私有）、邀请码申请、组织广场申请、管理员审批与任命、移除成员、组织内需求、成员筛选、`共同组织可见`联调 | owner 与 admin 均可审批、均可在名额内任命 admin；两个账号可分别走通「邀请码申请→审批通过」和「组织广场申请→审批通过」两条路径，之后在组织内发需求并看到对方组织内联系方式；owner 可移除成员 |
| M5 | 打磨：移动端适配、空状态、错误提示、微信分享 OG 预览（仅广场公开内容） | 主流程无阻断性体验问题，公开页在微信内转发有正常预览卡片 |
